      ◆ ABOUT THIS TOOL
      
What Is a JSON Web Token?

      
A compact, URL-safe way to pass signed claims between systems.

      

        
A JWT (RFC 7519) is three Base64URL-encoded parts separated by dots: a header describing the signing algorithm, a payload of claims such as the user ID and expiry time, and a signature that proves the token hasn't been tampered with.
JWTs are used for API authentication, single sign-on (OpenID Connect ID tokens), OAuth 2.0 access tokens and session cookies. Decoding one is the fastest way to debug “401 Unauthorized” errors, check roles and scopes, or see why a token is rejected.

        
The header and payload are only encoded, not encrypted — anyone holding the token can read them. Never put passwords or secrets in a JWT payload.
This tool decodes tokens; it does not verify the signature, because that requires the secret or public key. Never trust a token's contents in your application without verifying it server-side with a proper JWT library.

      

    

  


  
  

    

      ⏱ CLAIMS
      
Registered JWT Claims

      
The standard claims from RFC 7519 shown in the claims table.

      

        
ClaimNameMeaning

        
          
issIssuerWho created and signed the token (e.g. your auth server URL).

          
subSubjectWho the token is about — usually the user ID.

          
audAudienceWhich API or app the token is meant for. Can be a string or an array.

          
expExpiration timeUnix timestamp (seconds) after which the token must be rejected.

          
nbfNot beforeUnix timestamp before which the token is not yet valid.

          
iatIssued atUnix timestamp of when the token was created.

          
jtiJWT IDA unique identifier, used to prevent token replay.
