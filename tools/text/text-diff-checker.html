◆ ABOUT THIS TOOL

How the Diff Checker Works

It finds the smallest set of added and removed lines that turns the original into the changed text — the same idea behind git diff.

Both texts are split into lines and compared with the Myers diff algorithm, which finds a minimal edit script: every line is either unchanged, removed from the original, or added in the changed version. When a removed line is immediately replaced by an added one, the pair is shown as a modified line, and a second, word-level diff highlights exactly which words changed.

Ignore case and Ignore whitespace make the comparison forgiving — useful for re-indented code, text pasted from different editors, or capitalisation fixes you don't care about.

Side by side shows the two versions in parallel columns; Inline shows a single column with removals above additions, like a code review. On small screens Inline is chosen automatically. Long runs of unchanged lines are collapsed into folds you can expand, so you can jump straight to what changed.

Copy diff and Download .diff export the changes in the standard unified diff format (@@ -12,7 +12,8 @@ hunks with three lines of context), which works with patch, git apply and code review tools.

± READING A DIFF

What the Colours and Symbols Mean

The same markers are used on screen and in the exported unified diff.

−

Removed

Red lines exist only in the original. In a .diff file they start with -.

+

Added

Green lines exist only in the changed text. In a .diff file they start with +.

~

Modified

A removed line next to an added one. The darker highlight marks the words that actually changed.

@@

Hunk header

@@ -12,7 +12,8 @@ means: 7 lines from line 12 of the original became 8 lines from line 12 of the changed text.
