      How to Read a Cron Expression

      Five fields for Linux cron, six or seven for Quartz.

      A standard cron expression has five fields separated by spaces: minute (0–59), hour (0–23), day of month (1–31), month (1–12 or JAN–DEC) and day of week (0–7 or SUN–SAT, where both 0 and 7 mean Sunday). 0 9 * * 1-5 means “at 09:00, Monday to Friday”.

      In each field, * means every value, 1,15 is a list, 1-5 a range and */15 a step (every 15th value). Linux cron also understands @daily, @hourly, @weekly, @monthly, @yearly and @reboot.

      The day-of-month / day-of-week trap. If you restrict both day fields, Linux cron runs on days that match either one. 0 0 13 * 5 runs on every 13th and every Friday — not only on Friday the 13th. This tool warns you when that happens.

      Quartz (Java, also used by many enterprise schedulers) adds a seconds field at the front and an optional year at the end. Days of the week are numbered 1–7 starting on Sunday, and exactly one of the two day fields must be ?. Quartz also supports L (last day), W (nearest weekday) and # (e.g. 6#3 = third Friday).

      Time zones and DST. Cron runs in the time zone of the server (often UTC). Pick a zone to see real run times. When clocks change, a time can be skipped or happen twice; the run list marks those times and explains what Linux cron does.

      Probably because both day fields are set. In Linux cron, 0 0 1 * 1 runs on the 1st of the month and on every Monday — the two day fields are combined with OR. If one of them starts with *, both must match instead. The tool shows a warning whenever this applies.

      Quartz adds seconds at the start and an optional year at the end, numbers weekdays 1–7 from Sunday (standard cron uses 0–7, with 0 and 7 both Sunday), requires ? in one of the day fields, and supports L, W and #. Spring's @Scheduled also uses six fields, but numbers weekdays like standard cron — day names avoid confusion.

      The server's time zone, unless your crontab sets CRON_TZ (cronie) or your platform has a time-zone setting (for example Kubernetes timeZone). GitHub Actions schedules always run in UTC. Choose the zone in the run list to see the real times.

      Linux cron (cronie) runs fixed-time jobs from a skipped hour right after the clocks jump, and runs them only once when an hour repeats. Jobs with * in the minute or hour field simply follow the clock. Other schedulers may behave differently, so avoid scheduling important jobs between 01:00 and 03:00 local time — or use UTC.

      Quartz can: use L in the day-of-month field, e.g. 0 0 0 L * ?. Standard Linux cron has no “last day” option; a common workaround is to run on days 28–31 and check in the command whether tomorrow is the 1st.
