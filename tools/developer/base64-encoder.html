◆ ABOUT THIS TOOL

What Is Base64 Encoding?

A way to carry binary data through systems that only accept plain text.

Base64 converts any sequence of bytes into a string built from 64 safe characters: A–Z, a–z, 0–9, + and /, with = used as padding. Every 3 bytes of input become 4 characters of output, so encoded data is about 33% larger than the original.

It is used everywhere text-only channels need to carry binary content: email attachments (MIME), data URIs in HTML and CSS, JSON APIs that return files, HTTP Basic authentication headers and JSON Web Tokens.

This encoder turns your text into UTF-8 bytes before encoding, so accented letters, Chinese, Arabic and emoji encode correctly — a common bug with the browser's built-in btoa(), which fails on anything outside Latin-1.

Base64 is not encryption. Anyone can decode it instantly. Never use it to hide passwords or secrets — use it only to transport data safely.

⇄ VARIANTS

Base64 Variants Supported

Pick the flavour your destination expects.

+/

Standard Base64 (RFC 4648 §4)

The default alphabet with +, / and = padding. Use it for JSON payloads, APIs, configuration files and most programming languages.

-_

URL-safe Base64 (RFC 4648 §5)

Replaces + with - and / with _, and drops the padding. Safe in URLs, query strings, filenames and cookies — it is the format used by JWTs.

76

MIME (RFC 2045)

Standard Base64 broken into lines of at most 76 characters with CRLF line endings, as required for email attachments and some PEM-style formats.

://

Data URI (RFC 2397)

Adds a data:image/png;base64, style prefix so the result can be pasted straight into an <img src>, a CSS url() or an HTML attribute. The file's MIME type is detected automatically.
