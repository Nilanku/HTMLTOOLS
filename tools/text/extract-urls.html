◆ ABOUT THIS TOOL

How the URL Extractor Works

It finds links in any kind of text and cuts them off at the right place.

The extractor looks for links that start with http://, https:// or ftp:// — and, if you like, www. — then reads until the link ends. It works on plain text, HTML (href and src attributes), Markdown ([text](url)), JSON, CSV and server logs.

The hard part is knowing where a link stops. A full stop, comma, question mark or quote after a link is punctuation, not part of the URL. A closing bracket is only kept if the URL also contains the opening one — so (see https://example.com/page) gives https://example.com/page, while https://en.wikipedia.org/wiki/Mercury_(planet) stays complete.

HTML source. &amp; inside links is turned back into &, so links copied from page source work when you open them.

Tracking parameters. Remove tracking parameters deletes utm_source, utm_medium, fbclid, gclid, msclkid and similar — other parameters and their order are kept exactly as they were.

✓ WHAT COUNTS AS A LINK

Matching Rules

What is and isn't extracted.

✓

Always

http://, https:// and ftp:// links, including ports, IP addresses, localhost and non-English paths.

www

www. links (on by default)

www.example.com without a scheme — the ending must be a real domain.

?

Bare domains (optional)

example.com/page with no prefix. Off by default, because text like Node.js or readme.md can look like a domain.

✕

Never

Email addresses, mailto: and javascript: links, and relative paths like /about (they have no domain).
